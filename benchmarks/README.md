# Reproduce the OpenKeet 3.0 speech comparison

Run these on Windows from the repository root. Everything is Rust; no Python is needed. The setup in [audio benchmarks](../docs/benchmarks/audio.md) covers the model. [Baseline provenance](../docs/audit/PERFORMANCE_BASELINE.md) identifies the source and hardware. The Python baseline (archive A) is frozen in [results/python-baseline.json](results/python-baseline.json); the former Python harness that produced it was retired with the move to Rust.

1. Build the release audio CLI: `cargo build --locked --release -p copilot --features audio`. Set `LIBCLANG_PATH` to the directory containing `libclang.dll` when building whisper-rs on Windows.
2. Keep the original 116-clip synthetic pack or generate it with `target\release\copilot.exe bench-asr generate --stress`. Source text is in [stress-corpus.json](stress-corpus.json). The generated WAVs and their hashes live under `benchmarks/output/stress`. Regenerating produces different WAV hashes from the Python-era pack, so compare runs only on one pack.
3. With a release CLI built from archive B source `d2d8069`, run `target\release\copilot.exe bench-asr profile --cli <baseline-cli> --model models/ggml-small.en.bin --output benchmarks/output/baseline-3.0/profile`. It selects the same 25 clips and records process CPU and memory every 100 ms.
4. With the candidate CLI, run `target\release\copilot.exe bench-asr compare --baseline benchmarks/output/baseline-3.0/profile --cli target/release/copilot.exe --model models/ggml-small.en.bin`. It verifies manifest and WAV hashes and writes the table plus synthetic per-clip results to [results](results). If the baseline folder also holds the frozen Python run (`legacy-small.en.json` with its process metrics), the table keeps the Python column. Use separate `--scratch` and `--output` directories for repetitions.
5. For the larger live ASR pack use `target\release\copilot.exe bench-asr run --output benchmarks/output/stress --cli target/release/copilot.exe --model models/ggml-small.en.bin`. Add `--profile` for process metrics. Keep that output separate from the 25-clip process comparison.

For the short-speech comparison, run `target\release\copilot.exe bench-asr generate --stress --output benchmarks/output/short-followups --corpus benchmarks/short-followups.json`. Append the entries with conditions `one_word` and `control` from the stress manifest and resolve their WAV paths against the stress output directory. Run `bench-asr run` on this manifest with and without `--short-followups`. The [paired results](results/short-followups.json) contain every PCM checksum and the rejected hint variant. [Analysis](../docs/benchmarks/interview-stress.md#short-follow-up-mode)

Keep foreground activity low. Model load is process-cold and file-cache state is uncontrolled. Archive B should use the same Windows hardware as C.

For the separate desktop probe, retain the baseline release executable and run `powershell -NoProfile -File benchmarks/desktop-startup.ps1 -Before <baseline-desktop-exe> -After target/release/OpenKeet.exe -StartupOnly`. For current builds that hide the workspace when closed, `-StartupOnly` measures launch and process-tree memory, then stops the isolated test process. Use the same toolchain and release settings for both builds.

Do not commit private audio. The checked-in data is generated from the repository's synthetic recipes and Windows voices. Tests and profile commands need no paid credentials.
